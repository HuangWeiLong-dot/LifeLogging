# 运维手册

## 每天要跑的东西

```
23:00   run_daily.ps1
        ├─ cost_guard gate          预算预检
        ├─ collect_desktop.py       ActivityWatch（窗口标题 / AFK / 浏览器 URL）
        ├─ collect_phone.py         Dawarich
        ├─ ingest_gadgetbridge.py   手环
        ├─ normalize.py             规则归类 → 时间轴
        └─ generate_journal.py      AI 写日记
        周日额外：reconcile_cost.py
```

日志在 `state/logs/run_YYYY-MM-DD_HHMMSS.log`，保留 30 天。

## 排障

### 「今天日记是空的 / 内容很少」

按这个顺序查：

```bash
# 1. 采集端有没有数据
python scripts/collect_desktop.py --date today

# 2. 事件表里到底有什么
curl -H "X-API-Key: <key>" http://127.0.0.1:8787/days

# 3. 归一化结果
python scripts/normalize.py --date today
cat state/timeline-$(date +%F).md
```

90% 的情况是 **ActivityWatch 没在跑**，或者 `APP_RULES` 没覆盖你的常用软件
（看 timeline.md 末尾的「规则没认出来的应用」）。

### 「分类不准」

改 `normalize.py` 的 `APP_RULES`。规则是「小写子串包含」，
把更具体的关键词放前面。改完重跑 normalize 即可，不用动 AI。

如果 AI 也判错了，改 `generate_journal.py` 的 `SYSTEM_PROMPT` 里的边界规则。
**注意**：改系统提示词会让当天的 prompt cache 失效，那天会贵一些。

### 「费用比预期高」

```bash
python scripts/cost_guard.py report --days 7
```

看两个数：
- **缓存命中率** —— 低于 30% 说明 prompt caching 没生效。
  检查系统提示词是不是每天都在变（比如把日期拼进了 system 而不是 user）
- **每日调用次数** —— 超预期说明流水线被重跑了多次

降本手段（按效果排序）：
1. 多写 `APP_RULES`，规则覆盖率上去就不用 AI 兜底
2. 检查缓存命中率
3. 换 `claude-haiku-5-5` 跑分类，只在写复盘时用大模型（要改代码，未实现）
4. `max_output_tokens` 调小

### 「Dawarich 突然收不到位置了」

Android 后台限制是常态，不是 bug。依次检查：

1. 手机上 GPSLogger 的**「忽略电池优化」**还在不在（系统更新会重置）
2. 位置权限有没有从「始终允许」退回「仅使用时允许」（**这个最常见**）
3. 厂商自启白名单里 GPSLogger 还在不在
4. 服务器地址通不通（Tailscale 断了？）

参考 [dontkillmyapp.com](https://dontkillmyapp.com/) 上你机型的具体设置。

### 「.ps1 报 Missing closing '}'，但那个位置明明是对的」

**这是编码问题，不是语法问题。**

Windows PowerShell 5.1 读取 `.ps1` 时，如果文件**没有 BOM**，会按系统 ANSI 代码页
（中文系统是 GBK）解码。文件里的中文是 UTF-8 字节，被当成 GBK 解码后会错位配对，
**吃掉后面紧跟的 ASCII 字符 —— 包括大括号和引号**。于是解析器看到的代码和你看到的不一样，
报错行号还会指向一个完全无关的地方。

症状：报错行和你肉眼看到的内容对不上（差几行）。

确诊：
```powershell
# 无 BOM 会 FAIL，加 BOM 会 PASS —— 同一个文件，唯一变量是 BOM
$e = $null
$null = [System.Management.Automation.Language.Parser]::ParseFile(
    'C:\完整\路径\xxx.ps1', [ref]$null, [ref]$e)
if ($e.Count) { $e[0].Message } else { 'PASS' }
```

修复：把文件存成 **UTF-8 with BOM**。
```powershell
# PowerShell 里转
$p = 'C:\path\to\LifeLogging\scripts\run_daily.ps1'
$c = Get-Content $p -Raw -Encoding UTF8
[System.IO.File]::WriteAllText($p, $c, (New-Object System.Text.UTF8Encoding $true))
```

⚠️ **用编辑器（含 VS Code 的默认设置、大部分 Git 工具）改这些脚本后要复查 BOM。**
本项目所有 `.ps1` 都已带 BOM，改完跑一次：
```powershell
powershell -NoProfile -File scripts\check_ps1.ps1
```

### 「MCP 连不上」

Windows 上 90% 是 `npx` 的问题：

```powershell
# 错误写法
"command": "npx"
# 正确写法
"command": "C:\\Program Files\\nodejs\\npx.cmd"
```

其他检查：
- 改完配置**以管理员身份重启客户端**
- 路径用双反斜杠
- 前置服务（Obsidian、events_api :8787）确实在跑

## 数据安全

### 备份

**必须备份的**（丢了就没了）：
```bash
# 1. Obsidian 库 —— 最重要，这是你所有产出的位置
#    vault/ 目录，用 Git 或 Syncthing 都行

# 2. 事件表
$state\events.db
$state\events.db-wal     # ⚠️ WAL 文件也要，否则可能丢最后一批写入

# 3. 成本台账
$state\cost_ledger.jsonl

# 4. 服务器上的 Dawarich
docker exec dawarich_db pg_dump -U postgres dawarich_development > dawarich_backup.sql
```

**可以重建的**（不用备份）：
- `state/timeline-*.md/json` —— 重跑 normalize 就有了
- `state/logs/` —— 日志
- ActivityWatch 的原始桶 —— 重装可采，但历史就没了（所以还是建议一起备份）

### 磁盘占用

本方案**不录屏不录音**，所以没有大文件。ActivityWatch 的 SQLite 是纯文本窗口记录，
一年也就几十 MB 量级，不用操心。

（如果将来重新开启 screenpipe：默认约 30GB/月，那时才需要配置
`--fps`、`--video-quality`、`--retention-days` 来控制。）

### 隐私边界

| 数据 | 存在哪 | 会离开本机吗 |
|---|---|---|
| 窗口标题 / AFK / 浏览器 URL | `%LOCALAPPDATA%\activitywatch\` | ❌ |
| 位置轨迹 | 你的服务器 | ❌（除非 Dawarich 用了第三方 geocoding） |
| 健康数据 | 本机 SQLite | ❌ |
| 日记 | Obsidian 库 | ❌ |
| **送给 AI 的摘要** | Anthropic API | ⚠️ **会** |

**本方案不含屏幕/麦克风录制** —— 没有屏幕截图、没有音频文件、没有键盘记录。

电脑端采集到的全部内容是：
- **窗口标题字符串**（如 `main.py - LifeLogging - Code`）
- 装了 `aw-watcher-web` 扩展后，额外有**访问的 URL 和页面标题**

关于浏览器扩展的边界（值得说清楚，因为它采的是 URL）：
- 扩展只上报**当前活动标签页的 URL 和标题**，**不读页面内容、不截屏、不记录表单输入**
- **隐私/无痕窗口会被显式跳过**（代码里 `if data.get("incognito"): continue`），
  所以无痕里的访问不会被记录
- 只记录**活动标签页**，后台标签页不计时
- 它把数据发到 `http://localhost:5600`，也就是本机的 ActivityWatch，不出网

⚠️ 装扩展时注意**商店里有同名冒牌货**。只认官方 ID：
`nglaklhklhcoonedhgnpgddginnjdadi`（ActivityWatch）。另一个同名的
`fdlchjabjccnihpndlmkfobegggjpnhi`（Enfiniti Group）不是官方的 ——
装错等于把你访问的每一个 URL 送给不明第三方。

**最后一行是唯一的例外，要清楚**：日记生成时，时间轴摘要会发给 Anthropic。
摘要包含窗口标题（可能含文件名、聊天对象名）。要避免的话：

1. `ai.provider: ollama` —— 完全本地，零外传
2. 或在 `build_user_prompt` 里加脱敏：把窗口标题里的敏感词替换掉

Dawarich 的逆地理编码是内置的（本地做），不像 Reitti 默认走官方托管服务 ——
这也是当初选 Dawarich 的理由之一。

## 补跑历史数据

流水线漏跑一天：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run_daily.ps1 -Date 2026-10-12
```

⚠️ 但**采集端的数据可能已经过期**：
- ActivityWatch 是持久化的，补跑没问题
- Dawarich 同理，补跑只能拿到服务器上还留着的
- **手环数据**要从 Gadgetbridge 的导出文件补，所以那个文件的保留策略要宽松

所以：漏跑当天就尽快补，别拖。

> ⚠️ **补跑会消耗「今天」的预算额度**，不是被补那天的。
> 台账记的是调用实际发生的时间戳（`common.py` 里用 `datetime.now()`），
> 因为预算管的是「你今天花了多少钱」，跟数据归属哪天无关。
> 一口气补 5 天就会连扣 5 次钱 —— 补跑前先看一眼 `cost_guard.py status`。
